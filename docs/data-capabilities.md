# 数据能力与格式

[返回首页](../README.md)

这里描述 17.0.2 已有的代码能力。字段存在于协议中，不代表页面每次都会提供；结果必须保留缺失、缩写、截断、来源和观察时间。

## 平台字段

| 平台 | 作品与作者 | 媒体与互动 |
| --- | --- | --- |
| Bilibili | 动态 ID / BV 号、类型、标题、简介或动态正文、作者、发布时间、链接 | 封面、图片数量、点赞、评论、转发、收藏；动态和视频指标分开记录 |
| 小红书 | 笔记 ID、标题、正文、作者、头像、时间、标签；页面提供时含更新时间或地区 | 图片及尺寸、封面、可取得的视频链接、点赞、收藏、评论数、分享数 |
| 抖音 | 作品 ID、文案、作者、头像、时间、链接 | 封面、视频时长、点赞、评论、分享、收藏；播放数取决于响应 |
| 微博 | 微博 ID、正文、作者、头像、时间、链接、发布来源；响应提供时含地区 | 图片、点赞、评论、转发 |
| X / Twitter | 推文 ID、正文、作者名与账号、时间、语言、链接、回复/引用/转推关系、置顶标记 | 媒体类型、链接和尺寸；点赞、回复、转发、引用、可见的浏览及书签数 |

## 评论、截图与话题

评论计数只是指标。当前专用评论明细实现主要覆盖小红书，条数和详情导航需显式请求；不能由“返回评论数”推断已取得评论正文。

截图链路覆盖小红书详情及 Bilibili 作者/动态详情等指定路径，Bilibili 搜索不支持截图。不要从通用能力标志推断所有平台或任务均可截图。截图保存为本地证据，并记录时间与摘要。

微博普通话题分别保存帖子、观察到的发帖者关系、公开主页资料。关系仅代表实际观察到的作者和帖子，不代表完整参与者名单。主页资料按页面提供的昵称、简介、认证、标签、粉丝数等字段记录；不会递归获取粉丝或关注列表。超话明确不支持。

媒体链接不等于媒体文件。本项目没有通用视频下载、转码、OCR 或语音识别能力。

## 质量约定

- 未知值保留为空或缺失，不能改写为零。
- `1.2万` 等展示数值可解析为数值，同时保留原始展示和近似标记。
- Bilibili 的动态与视频指标按实体分别保留观测，避免混合口径。
- 同一平台、记录类别和原生 ID 的重复记录可以补齐缺失字段；不覆盖已确认值或把重复内容计作新作品。
- 计划的 `required_fields` 表示最低字段要求。条数足够但字段缺失时也不能声明完整成功。
- `field_groups` 记录字段组覆盖情况，不保证平台返回所有字段，也不额外授权详情、截图或评论采集。

## 导出接口

采集 CLI 保存 JSON。Python 模块 `media_missher_runtime.exporting` 提供 `ExportSelection` 与 `export_records`，支持 `xlsx`、`csv`、`json`、`jsonl`、`sqlite`。调用前需要把对应运行保存的记录按运行时合同读取和验证；本仓没有额外的通用 `export` CLI 子命令。

接口形态如下，完整参数见 [exporting.py](../runtime/media_missher_runtime/exporting.py)：

```python
export_records(
    records,                 # 已读取、已验证的本地记录序列
    selection,               # ExportSelection，包含真实 run_id、类别和格式
    destination_root=path,   # pathlib.Path
    run_status=status,       # 保留原运行状态，例如 complete 或 partial
    backend="cdp",
)
```

导出可按平台、目标、记录类别、字段和条件选择结果。不同记录类别分表或分文件；ID 按文本处理，表格公式前缀转义，到达 Excel 限制时拆分文件。默认不覆盖已有同名文件。

导出不会连接浏览器、补抓字段或将部分结果改写为完整成功。`run_status` 应由真实清单读取，不要因为接口存在默认值就省略状态核对。
