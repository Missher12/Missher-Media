# Media@Missher 15.5.0 / Bundle 0.5.0

本地私有升级候选。Git CLI 与 Harness 继续使用同一采集核心；新设备仍需先导入并选择博主，在用户明确要求后打开独立 AI 采集浏览器，由用户手动登录。安装、查看状态或导入名单不会自动采集。

## 共享保护

过去按 runtime home 分别保存采集锁和小红书状态。默认 Git/Harness 实际都使用 `~/.local/share/media-missher`；风险出现在另行配置不同 runtime home、但访问同一浏览器的情况。

现在 15.5+ 入口共用 `~/.local/share/media-missher-shared`，不以端口、CDP session 或 runtime home 划分额度。共享范围是同一用户 HOME，独立浏览器也串行；它不能协调另一系统用户/另一 HOME 或未知旧客户端，Agent 不得通过切换这些配置规避暂停。

采集先取得安装生命周期锁、用户共享采集锁及已登记安装的旧采集锁，再进行前置检查。直接运行新版核心也取得共享采集锁。父控制器把实际锁描述符交给子核心，核心逐个核对私有文件类型、权限、所有者、inode 和独占锁；一个环境布尔值不能绕过检查。父进程关闭描述符后，尚在运行的子核心仍保持共享锁；正常停止仍先排空自有采集进程，再释放保护，不关闭 Chrome。

已配置的当前 runtime home、默认 home 和之前登记的 home 会保存在私有登记文件。合并小红书状态时取最大启动时间、保留任何未确认风险；旧状态锁覆盖整个新版批次，新的时间和风险也同步写回已知旧目录。先验证所有旧状态，再写共享和旧副本；任一副本损坏或权限异常都会停止。路径带 `..` 时先排除链接再规范化，避免登记不一致。

明确的本地风险确认会同步写回已知副本，**不会清除 600 秒间隔**，不会发起采集。确认过程中断可能保守保留暂停；以后发现未知旧目录仍有暂停，也会再次保留它。不要删除状态文件、登记文件或锁来“修复”。登记容量 64 个 runtime home，超过时停止并要求人工检查。

已知旧入口的锁和状态得到兼容保护，但旧程序本身没有变成新版。应停止旧采集进程，再使用本候选安装器升级实际使用的入口；不能让未知旧程序与新程序同时操控浏览器。

小红书仍是最多 10 条、3 页、至少 600 秒启动间隔，保留详情停留和翻页检查；无自动重试、代理轮换、账号切换或验证绕过。这些是本地保守限制，不是平台批准的安全额度。

## 版本预检

安装器可由系统 Python 引导，但运行环境使用 Python 3.11/3.12，以匹配当前固定依赖。自动选择本机已有的兼容解释器；即使用 3.14 启动安装器，也不会拿它创建不兼容环境。缺少兼容解释器时在安装前明确停止。升级时仅在暂存区重建不兼容的旧环境，失败仍保留原安装。

`preflight.py` 与 `run_collection.py` 共用严格、只读的 VERSION 校验。旧核心会返回可识别的当前版本、所需 15.5.0 和安装对应版本的提示；在 Python 依赖探测、CDP 请求或创建 run 之前停止。错误或不可安全读取的 VERSION 只显示 unavailable，不回显任意文件内容。预检不会自动安装。

## 面向 Agent 的默认使用方式

Bundle 安装激活后注册 `media_missher_setup`、`media_missher_collect` 和 `media_missher_runs`。工具参数和说明携带操作规则；支持原生 `systemPrompt.section` 的 Harness 还会收到 `media-missher:agent-guidance` 简短流程。该可选服务缺席时工具照常注册，不伪造宿主接口或另行注入消息。完整参考仍随包保留在 AGENT.md；不依赖本次对话或维护机器的路径。

Agent 根据用户当前任务使用工具：先检查目标，再导入/选择，按明确意图打开浏览器并引导人工登录，沿用已取得的授权采集，最后展示实际计数和私有结果。安装成功不是采集授权，也不证明当前任务已经看到工具；工具实际可见才说明宿主已激活。

阶段进度走独立的固定结构通道，保留控制器最终 JSON。只有固定阶段、平台、计数和 monotonic 耗时进入进度；不记录目标、账号、URL、正文或凭据。当前 Harness SDK 没有原生实时进度回调，Agent 可用 `media_missher_runs` 的 `progress` 动作查看最近一次调用的本地快照；它不发起第二次采集，也不把最后观测状态当作进程存活证明。进度目录不可用时保留现场，固定提示 `local-progress-unavailable`，继续处理实际结果。

控制器返回 `phase_timings` 和 `phase_timings_persisted`，私有 run 内保存 `phase-timings.json`；Bundle 在 `.progress/` 为每次调用单独保存有界快照。固定阶段为 controller-preflight、engine、browser-preflight、platform-collection、validation、output 和 run；每行包含 schema/phase/state/elapsed_ms，终结事件另含 duration_ms，平台采集另含 platform/completed/requested。阶段按实际代码边界计时；浏览器连接和页面预检合计，平台采集包含列表、详情和评论，嵌套阶段不能相加。工作簿保持六表，Summary 新增阶段耗时，不把 Harness 工作簿生成时间算进控制器耗时。

## 验证与分发边界

`run` 是本次控制器/核心执行范围内的总耗时，不是从 Agent 发起到工作簿完成的端到端耗时。上层 profile 校验、版本/共享锁门槛、Harness 安装和工作簿生成均不包含在控制器计时内。

最终测试、包大小和 SHA-256 记录在 `harness-plugin/dist/SHARED-SAFETY-EVIDENCE.json`。15.4.0 在 2026-09-08 的四平台各一条实测仍是旧版证据；本版不以旧数据冒充新的真实平台测试。离线保护测试、合成采集、真实 Harness 加载和实际平台采集分别报告。
