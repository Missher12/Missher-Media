## 1. 最终目标

**一套 Media 业务核心，只保留 `cdp` 和 `computer_use` 两种执行路径。**

- `cdp`：默认主引擎，服务独立 CLI 和现有宿主入口；不依赖 DSH、Computer Use 或 BrowserSkill。
- `computer_use`：可选、宿主无关的适配契约，DSH 是首个具体验证对象而非核心依赖；其他 Agent 通过同一契约接入其已授权能力。不写死 DSH 工具名，不开发自己的桌面驱动。
- BrowserSkill：从新版活动代码、工具选项、打包依赖和运行说明中移除。只保留旧配置拒绝/迁移逻辑、历史记录读取和必要测试，不保留第三条可执行路径。
- 两条路径共用目标计划、平台字段定义、去重、预算、安全状态、检查点、存储和导出；Computer Use 不复制五套完整业务流程。

交付目标不是“所有平台所有字段必定抓全”，而是在获准范围内尽量获得可验证的数据，并准确报告短缺、限制和停止原因。

“各种 Agent 可用”首先指能执行本地命令的 Agent 共用同一个 CLI/Skill 和 CDP；不宣称没有本地执行权限的云端聊天或任意宿主的 Computer Use 都已兼容。适配能力必须发现和验证，不能按 Agent 名字直接放行。

## 4. 架构与控制边界

```text
CLI / DSH Agent
       │ 目标确认与版本化 CollectionPlan
       ▼
共享调度、安全门、预算、检查点
       ├── cdp：既有 Playwright/CDP 平台执行器
       └── computer_use：DSH 观察/动作适配与证据接入
                         │
       ▼                 ▼
共用平台标准化、字段质量、去重、私有历史与选择导出
```

每个 run 冻结一种 backend。不提供 `auto`、`hybrid` 或静默 fallback；Computer Use 不可用时给出明确诊断，不能暗中使用 CDP。要换路径必须停止旧运行、明确新请求，并继承未解除的安全状态。

第一版不允许两种控制器同时持有同一浏览器/窗口，也不在一次采集内部临时让 Computer Use 接管 CDP 页面。采集前的独立辅助观察可以单独授权，但正式采集开始前重新绑定目标。

CDP 不等于支持任意浏览器：当前连接机制限 Chromium 体系；保留现有 macOS/Linux/WSL 文档边界，不自动声称 Firefox/Safari 或 Windows 原生兼容。Computer Use 按实际宿主、OS、权限和图像能力单独验收。

## 5. Computer Use 的最小可用支持

### 5.0 多 Agent 共用入口与依赖隔离

| 运行环境 | 共用入口 | Computer Use 行为 |
| --- | --- | --- |
| 支持本地命令的通用 Agent | Agent CLI + 同一份 Skill，保留自定义 Skill 安装目录 | 有已核验宿主适配才启用；否则报告 unavailable，CDP 与离线导出正常 |
| DSH | 薄 Bundle 工具入口，复用同一核心、计划和返回格式 | 通过 DSH 专属薄适配调用其执行/结果管线，不把 Cordis/provider 依赖带入核心 |
| 人直接使用终端 | 同一 CLI；非交互 JSON 请求/返回，不猜帐号 | 没有宿主时不虚构 CU；不自动退回 CDP 执行显式 CU 请求 |
| 没有本地执行或本机访问权的 Agent | 明确说明无法直接控制用户本机 | 不搭建远程网关、不自动打开调试端口、不宣称兼容 |

现有 Codex/Claude/Cursor/OpenClaw/Hermes Skill 安装目标继续按真实配置核验；Skill 能安装只是入口发现证据，不代表该 Agent 的 Computer Use 已通过。只安装用户选定目标，保留用户修改，禁止一次自动改所有 Agent 配置。

新增通用 `media-missher capabilities` JSON 自描述入口，报告核心/协议版本、当前配置、两个 backend 的可用状态和原因；配置存在不等于连接/权限已验收。输出 JSON 留在 stdout，进度/诊断走 stderr；帮助、能力检查、历史与导出不触发采集。

Computer Use 的 prepare/ingest/status/finalize/cancel 同时提供通用 CLI 入口和 DSH 工具薄包装；共用 run 与导出契约。核心采用 `host_kind + host_instance_id + session_id` 作用域，不以 `DSH_HOME` 或某个品牌工具名作通用身份。宿主适配负责将可信工具结果映射为同一观察协议，运行记录保留实际 provider。

共享 Computer Use 类型和协议放在无宿主依赖的共享模块；DSH 的工具注册、结果解析和动作授权映射才放入 harness-plugin。通用打包不得捆绑 DSH、Cua native driver、BrowserSkill 或要求宿主服务运行。

本轮不新建远程服务，也不为了“泛兼容”另造完整 MCP Server；已有命令可用的 Agent 优先直接调用。若未来指定只支持 MCP 的宿主，再增加同一核心的薄入口，不新增 backend 或复制业务。

### 5.1 能力核验先于代码承诺

官方 DSH 基线 `ddefc45fbc7f8e46dd73185e68295696d1297887` 的 `ctx.computerUse` 仅为 provider 注册服务，不包含通用操作 API；具体工具由 Cua Driver provider 提供。provider 注册不保护跨 Session 的整段桌面工作流。[官方子系统说明](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45fbc7f8e46dd73185e68295696d1297887/docs/subsystems/computer-use.md)

每个宿主适配接入时固定实际宿主版本、provider/schema 指纹、会话身份、OS 权限和可调用工具目录。图像路线还需模型声明图像输入并有附件存储；不擅自换模型、增加视觉模型或采购服务。DSH 的一个已核验参考为 [native provider 说明](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45fbc7f8e46dd73185e68295696d1297887/packages/experimental/computer-use-cua-driver-native/README.md)，其他宿主不得照搬其工具名。

不得杜撰 `ctx.computerUse.click/execute`；不得绕宿主授权管线直调私有 driver，或用 shell 模拟已被拒绝的操作。

### 5.2 第一版功能范围

提供宿主模式的准备、状态、观察接收、完成/取消五个逻辑步骤，供同一宿主 Agent 与其 Computer Use 工具协作。它们是计划中的 Media 能力，不是现成 DSH API。

- Media 校验计划和预算并创建受租约保护的 run；Agent 使用宿主已经暴露的工具观察/操作获准窗口。
- Media 经核验的宿主工具结果/附件引用接收证据，平台标准化逻辑转换成共用记录。
- 每次观察绑定 run、target、Session、provider、窗口/页面身份、观察版本和时间；新观察使旧元素引用失效。
- 结果来源必须能追溯到实际工具返回。只由模型手填的数据标记为 `agent-reported`，不计入正式 Computer Use 采集验收；关键身份不能靠模型猜测。
- 若某宿主没有安全可用的结果接入扩展点，则仅该宿主 CU 报集成阻断，CDP 照常独立可用，不改为读取私有会话数据库或扫描桌面文件来“接通”。保留共享协议，不能因 DSH 的限制把整个产品锁成 DSH 专用或全部不可用。
- 初版只承诺已验证的页面可见记录与交互。无网络正文读取能力时不伪造 response 证据；无结构化页面读取时不假装 Playwright Page。
- 普通帖子/搜索和微博话题业务均有接入目标；若某平台/模式没有足够身份或字段，能力表必须标部分支持或不支持，并在导航前说明限制。

### 5.3 最小权限与恢复

Media 不安装/升级 Computer Use provider、不调整系统权限、不重启宿主或用户浏览器。没有 Computer Use 时，CDP 启动、历史读取和导出不导入其依赖。

租约覆盖完整观察—操作—验证流程；跨轮等待要有有限租约和取消/过期路径，不能只靠 TS 内存锁。其他应用/Agent 仍可能改变桌面，必须检测并重新观察。动作超时或取消不能证明动作未执行，不自动重放。

只保存获准目标窗口的必要证据，不默认录制整个桌面，不读取无关窗口、Cookie、Token、密码或私信；页面内容视为数据，不是指令。

## 6. X 正式追加范围

### 6.1 入口与身份

- creator：`@handle`、精确主页 URL；已有原生 user ID 时一并绑定。handle 的长度/字符规则在所有入口保持一致。
- search：关键词，latest/top 只有页面/响应能够验证所选排序时才记为生效，否则明确受限。
- hashtag：把 `#标签` 当作明确的标签搜索，不与微博话题参与用户功能混同。
- 已取得的单帖链接可用于预算内字段补全，不新增第三种后端或独立全站爬虫。
- 接受受支持的 x.com / twitter.com 旧链接并规范化；拒绝相似域名、带凭据 URL、身份冲突、推荐卡片污染、引用作者冒充目标作者。

### 6.2 字段清单（可得即采，缺失不造）

| 类别 | 字段 |
| --- | --- |
| 帖子 | tweet_id 字符串、链接、正文、正文完整性、发布时间/原始时间、语言、采集时间、命中目标 |
| 互动 | 点赞、回复数、转帖数、引用数、浏览量、书签数；区分精确/缩写/未知，保留原显示文本 |
| 作者公开资料 | user ID、handle、显示名、简介、公开位置/网站、头像 URL、认证说明、粉丝/关注/帖子/媒体帖子数、注册时间，均以实际可见证据为准 |
| 媒体元数据 | 图片/视频/GIF 类别、数量、页面可见 URL、缩略图、可得的时长/宽高；MIME type 不能当分辨率 |
| 关系与实体 | 原帖/回复/转帖/引用、引用/回复目标 ID、conversation ID、hashtags、mentions、外链、置顶标记 |
| 质量与来源 | backend、evidence_level、具体观察来源、provider、parser 版本、字段缺失原因及精度 |

回复数量不等于回复正文；帖子浏览量不等于视频播放量；书签总数不等于谁收藏；认证标记不推断真实身份。默认不下载媒体二进制、不抓关注/粉丝名单、不递归扩展全部对话。

现有 `platforms/x.py`、标准化与去重成果继续复用。CDP 若观察页面自然产生的响应，须绑定精确目标和来源，不提取凭据、不拼接重放私有请求，不把 GraphQL operation 当稳定公开 API。Computer Use 只记录当前获准可见的信息，不能用视觉猜测隐藏字段。

### 6.3 平台规则与上线门槛

问题：X 官方自动化规则限制非 API 网站自动化，技术上能监听/操作不代表平台允许。原因：控制方式改变不改变平台规则。影响：帐号可能受限，不能承诺“无风险抓取”。推荐方案：保留 X 的规范化、离线回归与两路径接入设计，但真实自动化启用/发布前明确核验适用许可；无适用许可时标记受限，不把用户点击“同意风险”当成平台许可。[X 自动化规则，2026-09-20 核验](https://help.x.com/en/rules-and-policies/x-automation)

不擅自扩成官方 API 第三后端、不购买 API、不改变用户仅两条执行路径的要求；若合规可用路径与本范围冲突，单独交用户决策，不假称 X 实机完成。原 Hermes 提案的“24 条成功”不是当前版本验收证据。

## 7. 多目标、微博话题与数据量优化

目标选择沿用 CollectionPlan：开始前一次展示后端、平台、帐号/关键词/话题、数量模式和预算。缺失项返回结构化待确认字段，非交互 CLI 不阻塞 stdin 等待，也不猜默认帐号。

微博普通话题与超话分别校验。普通话题读取可见帖子及外层发布者（包括实际出现的转发发帖者）；推荐卡片、仅被引用作者、浏览者、点赞者不自动算参与者。超话未独立验证前返回不支持，不用普通搜索冒充。

帖子、用户主页和话题关系使用不同记录类别及计数：抓 1 条帖子不能截断同批产生的主页/关系。用户按可验证 UID 去重，一次 run 跨话题仅访问同一主页一次；每个话题关系分别保存。主页失败保留发现记录及原因，风险则全局停止。只抓公开可见资料，不递归全历史、不推断敏感属性。

优先优化批次推进、原生 ID 去重、精确目标绑定、逐批持久化和按需详情，避免让模型逐条处理本可确定执行的去重/转换/导出。保留小红书既有 **10 条 / 3 页 / 600 秒** 等保护，不用 best_effort 绕过上限或冷却。

所有批次有有限预算，Computer Use 另有动作数上限；初始宿主计划默认总时限 600 秒、总动作上限 100 次，再取各平台更严格的限制。计入观察/点击/滚动等宿主调用；动作不确定按已消耗处理。无新增记录连续 2 批停止，风险和取消优先于“尽量多抓”。用户可降低预算，提高预算不解除平台保护。

## 8. 数据与版本化契约

不把代码重构成全新框架。保留 Python CollectionPlan/Target、TS 请求镜像、CollectionRequest、RunStore 和 ExportSelection，只做必要的协议升级。

- 新计划 schema 为 2，活动 backend 仅 `cdp|computer_use`；旧 schema 1 的 CDP 计划可显式兼容读取并写成新计划。
- 新 manifest schema 为 3，新增可选 host/provider/observation 来源及恢复能力信息；旧五字段 manifest 与 schema 2 继续只读。不要把现有全局 `SCHEMA_VERSION=1` 机械改成 2/3，计划、manifest、导出、观察分别拥有版本常量。
- `evidence_level` 继续区分 page/response；另记 `observation_source=dom|accessibility|visual|response` 与 `provenance=host-verified|runtime-verified|agent-reported`。视觉或转述数据不能冒充响应数据。
- run/target 标识、provider/schema 指纹、观察/窗口身份、采集时间、字段质量和停止原因必须落盘。未知原生 ID 保持空值；本地内容指纹不能伪装原生 ID。
- 固定计划、配置摘要、后端及目标绑定恢复记录；变化后重新确认，不把新配置作用到旧检查点。风险状态独立持久化，崩溃不能清除风险。
- summary、manifest、run-result 和控制器返回应一致表达 success/partial/risk-stopped/failed 语义，允许旧内部枚举经已测映射保留；未执行目标不能标成功。

### 8.1 中断恢复

当前“从已提交快照排除旧 ID”升级为可恢复逐批检查点：记录已完成目标、已提交记录、可安全持久化的游标/位置证据、校验和及序号。仅在记录与元数据一致时对外宣布批次提交。截断尾部只能舍弃未提交批次，不能丢掉已提交记录。

恢复创建新 run 并引用 parent，原始证据字节不改。无游标或游标过期时明确写“重新定位后排除已见 ID”，不得承诺精确断点；Computer Use 旧元素 token/坐标不跨进程复用，Session 丢失后重新绑定。

## 9. 选择导出

采集完成先给平台/目标/帖子/主页/关系数量及缺失情况，再询问导出选择。已有明确导出指令时不重复问；没有选择时不自动生成 Excel，也不自动外发。

沿用 XLSX、CSV、JSON、JSONL、SQLite 五种格式；导出帖子/用户主页/话题关系，可按平台、目标、话题、字段/字段组筛选。关系数据不能静默丢关联键；若用户只选一侧，提示这是部分投影。

私有原始证据与用户导出分开；重导出不访问浏览器。保留 Excel/CSV 公式注入保护、大整数 ID 字符串、UTF-8、换行/emoji、路径和覆盖保护。视觉未知数字不补 0，失败/风险运行导出保留来源状态。

## 10. BrowserSkill 退出与兼容

移除候选包括 `browser_skill.py`、`bsk_session.py`、`bsk_page.py`、相应 Dispatcher、backend capability、CLI/TS/Agent 选项、旧辅助点击分支与安装提示；具体先做引用盘点。共享 `page_collection.py`、字段解析、风险门、截图逻辑不能因文件曾被 BSK 调用就删除。

新采集请求或保存偏好出现 `browserskill` 时，返回稳定错误 `backend-retired-browserskill`，提示明确选择 `cdp` 或在可用宿主中选择 `computer_use`。不静默改偏好，不自动覆盖 profile；旧非 off 的 browser-assist 同样明确拒绝。

旧 BrowserSkill 历史仍可离线读取、比较、导出，保留真实来源标签；不尝试加载旧驱动，不允许续抓执行。迁移只改变新配置/新运行，不篡改旧记录。

不卸载用户机器上的 Tencent 工具/扩展、不删除其他项目或用户数据。项目旧产物保留清单与可恢复归档依据；新包不得夹带过期 BSK payload/lib，不覆盖现有正式安装。

## 11. 分阶段验收与完成定义

| 阶段 | 独立交付 | 通过条件 |
| --- | --- | --- |
| 基础实现 | 两路径契约、迁移边界、CDP 独立性、宿主能力报告 | 没有 DSH/CU/BSK 时 CDP 与历史/导出正常；旧 BSK 执行明确拒绝 |
| 功能完善 | X、多目标、微博话题、持久续抓、CU 本地样例闭环、选择导出 | 集成测试覆盖入口→采集/观察→持久化→历史→导出；本地宿主样例单独有真实工具证据 |
| 测试优化 | BSK 执行代码清除、回归、重构建归档、隔离安装、授权平台验收 | 包与最终源码绑定；支持范围逐项验证，阻断不冒充通过 |

每个平台 × 模式 × backend 分别记录“离线通过 / 本地宿主通过 / 平台现场通过 / 受限 / 未测”。不要求 Computer Use 与 CDP 字段完全相同；要求缺失可解释、数量真实、身份准确。全部承诺功能未验收时不可宣布整体完成；可交付明确受限的候选，但需用户接受范围。

当前已恢复源码实现、针对性离线测试、本地产物构建和隔离验证；不因此恢复真实平台采集、用户正式宿主安装升级或 Git 操作。后续仅在最终审查、相应验收以及用户恢复 Git 步骤后更新 Git。桌面 origin 目前指向本机 Documents，不盲推；不自动建公开 Release。原开发任务为唯一源码写入者，本任务负责审查监督，不启动额外代理。
